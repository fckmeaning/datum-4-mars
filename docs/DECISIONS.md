**D-12 · Образец оболочки: Sol Atlas (H+7).**
- Оператор прислал https://sol-atlas.netlify.app/ (проект другой команды Space Apps 2026 про кратер Езеро) как образец. Заимствуем только паттерны взаимодействия, не код, ассеты и название:
  1. вход через глобус (глобус Марса, подписи площадок, «спуск» к выбранной);
  2. верхняя панель: Mission SOL, LMST, Ls, задержка связи с Землёй;
  3. правая панель слоёв с горячими клавишами 1–6 и тумблеры отображения;
  4. нижняя панель: высота камеры (ALT), DATA SOURCES, AUTOPILOT (автоматический тур для демо), REC и SOUND как P2;
  5. загрузочный экран со списком реально загружаемых данных (берётся из /sources);

- Наше отличие и ставка: автономная ориентация без GPS и компаса, маршрут «быстрый ↔ безопасный» с запасом на возврат, радиация, термика, математика F01–F53.

- Эндпоинты: `GET /sites/{id}/clock` (часы миссии) и `GET /sources` (манифест данных) — контракт v1.1, аддитивно.

**D-13 · Источник правды по координатам мест (H+7).**
- Проверка отчёта W1 показала ошибки в «подтверждённых» координатах до 1,7 км (boxwork по долготе 1,2 км, Yellowknife Bay 360 м, Pahrump Hills 1,7 км по широте). Источник у W1 был общая страница карты, а не файл данных.
- Правило: координата места допустима только если получена из измеренных данных (MMGIS-точки ровера по солу, газетир USGS API, файл миссии) с записью файла и способа извлечения. Слово «confirmed» требует ссылки на файл данных, а не на страницу.
- Реальные данные: `MSL_waypoints.json` (1389 точек, солы 3–5073), `MSL_waypoints_current.json`, `MSL_traverse.json` на mars.nasa.gov/mmgis-maps/MSL/Layers/json/. Из них сделаны `places.json` и `traverse.geojson`.
- Район boxwork (солы 4600–4700): широта −4,8087…−4,8042, долгота 137,3791…137,3817, высота −3633…−3605 м. Весь траверс помещается в AOI (широта −4,826…−4,589, долгота 137,353…137,449).

**D-22 · Кольцо дальности пина, постоянный HUD в стиле Sol Atlas, вход в экспедицию (2026-11-14, оператор).** (1) Старая страница `/planner` удалена; адрес перенаправляет на `/site/gale`, все кнопки ведут на страницы экспедиций. **D-27 · Сайт полностью статический, API необязателен (2026-11-14, оператор).** Оператор спросил «нахера нам API» и решил: публикуется папка файлов (`npm run build` → `apps/web/dist`), Python API остаётся в репозитории как дополнение (`Dockerfile`, `deploy/`, `docs/DEPLOY.md` для варианта с API не удалены), сайт от него не зависит и в продакшене не делает ни одного запроса на `/api`. Номер D-26 к этому моменту занят планом плоской карты, поэтому решение записано как D-27.
- **В браузере:** сол миссии, LMST, Ls, задержка Земли, высота и азимут Солнца, положения орбитеров, поиск мест, экспорт маршрута RFC 7946, планировщик вылазок (`sites/eva`, как и раньше). Порт Mars24, F49 и F52 на TypeScript лежит в `apps/web/src/static/marsTime.ts`, тесты сверяют его с числами Python (Perseverance сол 2039, Gale сол 5074, задержка 659 с на 2026-11-14T08:31:31Z, положения MRO и других орбитеров).
- **Космическая погода:** живой запрос браузера к NASA DONKI (CORS открыт; опубликованный публичный `DEMO_KEY`, своего ключа в сборке нет); при отказе снимок `public/data/static/space_weather.json`, каждое сообщение помечено «snapshot of <дата>, not live».
- **Заранее посчитано Python-ядром** (`data/pipeline/make_static_routes.py`, вызывает настоящий FastAPI в процессе): маршруты Gale от базы к каждому именованному месту (SAFEST, FASTEST, три профиля, ровер + walkback, путь домой), видимость F10, изохроны возврата, сводка проходимости, источники, орбитеры; файлы в `apps/web/public/data/static/` (4,4 МБ). Время старта маршрутов зафиксировано (2026-11-14T08:30:00Z), стоимости, зависящие от Солнца, относятся к нему.

MSW в продакшен-сборку не попадает (`mockBoot` не запускается и вырезается).
