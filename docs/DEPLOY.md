# Публичная сдача: хостинг API + веб одним сервисом (решение оператора по D-07: «хостить API»)

Статус: **файлы готовы, ничего не развёрнуто.** Деплой, аккаунт у провайдера, ключи и `git push` делаются только после явного «да» оператора (правила в `docs/STATE.md`).

## 1. Что собрано
Один образ = API + собранный фронтенд на одном адресе (клиент ходит на относительные `/api/v1` и `/data`, поэтому CORS и правка клиента не нужны).

| Файл | Назначение |
|---|---|
| `Dockerfile` | стадия 1: `npx vite build` (без `tsc`, карты исходников удаляются, ≈2,7 МБ); стадия 2: Python 3.12-slim, зависимости, пакет `marsnav`, `config/`, `contracts/`, `data/manifest.yaml`, `data/processed/`, прогрев numba |
| `.dockerignore` | исключает `.venv`, `node_modules`, `data/raw`, `conveyor`, `prompts`, `docs`, `tests` и т. п. |
| `deploy/requirements-deploy.txt` | `requirements.lock.txt` без pytest/hypothesis/ruff/scikit-image и их зависимостей (33 пина из 47) |
| `deploy/warm.py` | прогревает numba и кэши до первого запроса |
| `apps/api/app/main.py` | `SPAStaticFiles` (подмена на `index.html` для `/planner`, `/globe`…, но не для `/api` и `/data`), `MARSNAV_CORS_ORIGINS`, `MARSNAV_WEB_DIST` |
| `apps/api/tests/test_web_dist.py` | тесты раздачи фронтенда |

Переменные окружения: `PORT` (по умолчанию 8080), `MARSNAV_CORS_ORIGINS` (доп. источники через запятую, нужна только при размещении фронтенда на другом домене), `NASA_API_KEY` (необязательно, секрет провайдера; без него космическая погода идёт через публичный `DEMO_KEY` с кэшем 30 мин). **Ключ в образ не запекаем.**

## 2. Что проверено и что нет
Проверено на этой машине (Windows, без Docker):
- `vite build` в изолированной копии, где есть только `apps/web` и `contracts/projection.json`: проходит (сборка зависит от `contracts/projection.json`, он копируется во второй стадии).
- Одноадресный режим на реальном `uvicorn`: `/` и `/planner` отдают `index.html`, `/api/v1/health` — JSON, неизвестные `/api/...` и `/data/...` — 404 JSON, Range-запрос к GeoTIFF — 206 с `content-range`.
- Прогрев с заблокированным импортом всех исключённых dev-пакетов: проходит (значит `requirements-deploy.txt` достаточен). Первый запрос маршрута 7,5 с (компиляция numba), следующий 0,09 с.
- API-тесты: 19 прошли.

**Не проверено:**
1. Сама команда `docker build` и запуск контейнера (на машине нет Docker); пины 2026 года надо подтвердить установкой на Linux при первой сборке.
2. Потребление памяти и время маршрута на L3 (3,1 млн ячеек): L2/L3 ещё догружаются (8 из 11 полос). Брать запас от 2 ГиБ ОЗУ.
3. Холодный старт контейнера на выбранном провайдере (кэш numba зависит от процессора: при другом CPU компиляция повторится, потому и есть прогрев при старте).

## 3. Данные в образе
`data/processed/` в `.gitignore`. Варианты:
- Провайдер, который загружает локальную папку (Cloud Run `--source .`, Fly `deploy`): данные берутся из рабочей папки, git не нужен.
- Провайдер, который строит из git (Hugging Face Spaces, Render): нужен репозиторий с данными. Вес малый (сейчас 2,1 МБ, с L2/L3 будет порядка десятков МБ): `git add -f data/processed/gale data/processed/*.json`. **Публичный репозиторий создаём и пушим только по вашему «да».**

## 4. Варианты хостинга (нужен выбор оператора)
| Провайдер | ОЗУ | Цена/аккаунт | Особенности |
|---|---|---|---|
| Hugging Face Spaces (Docker) | до 16 ГБ бесплатно | аккаунт HF, бесплатно | порт 7860, в `README.md` Space указать `sdk: docker`, `app_port: 7860`; сборка из git; **рекомендую** для демо |
| Google Cloud Run | 2 ГиБ и больше | аккаунт Google, платёжная карта | `gcloud run deploy --source . --memory 2Gi --min-instances 1`; на машине нет `gcloud` |
| Render | free 512 МБ мало | платный тариф | сборка из GitHub |
| Fly.io | от 1–2 ГБ | карта | CLI не установлен |

Firebase Hosting (CLI установлен) раздаёт только статику и для API на numba/rasterio не подходит.

## 5. Порядок выхода в продакшен (после «да» оператора)
1. Оператор выбирает провайдера и сам создаёт аккаунт/вводит платёжные данные; ключи вводит оператор.
2. `docker build -t marsnav .` и `docker run -p 8080:8080 marsnav` на любой машине с Docker (или первая сборка у провайдера); смотреть в логах строки `warm ...`.
3. Проверка: `GET /api/v1/health` (поле `data_levels` должно содержать `L2`/`L3`), открыть `/`, `/planner`, `POST /api/v1/route/alternatives` (≈ до 10 с в первый раз, затем быстро).
4. Записать публичный URL в `submission/SUBMISSION_TEXT.md`.
5. Откат: переключить трафик на предыдущую ревизию или остановить сервис.
