TICKET T-103 | lane: W1 | priority: P0 | depends_on: [T-102] | due: H+6 | contract: v1

GOAL: data/processed/orbiters.json lists the orbiters that are active today with orbital elements taken from a verified source, so the API (/orbiters, /orbiters/states, /comms/windows) and the Globe mode show real spacecraft instead of nothing.

CONTEXT
- The API already reads data/processed/orbiters.json (format below) and propagates the elements with two-body Kepler motion + J2 drift (marsnav.orbits). Elements are assumed to be in the Mars-equator inertial frame whose x axis is the ascending node of the Mars equator on the ICRF equator (the frame in which the IAU prime-meridian angle W is measured). If your source gives another frame (e.g. ICRF/ecliptic), do NOT convert silently: say exactly which frame it is in your report and in the file's "frame" field; the CEO converts.
- Candidate spacecraft (verify that each is active today and find its ID; do not rely on memory): Mars Reconnaissance Orbiter, Mars Odyssey, MAVEN, Mars Express, ExoMars Trace Gas Orbiter, others if active. relay_capable = true only for spacecraft documented as relays for surface assets (check the source).
- Source suggestion: JPL Horizons API (https://ssd.jpl.nasa.gov/api/horizons.api) with EPHEM_TYPE=ELEMENTS and the Mars centre; look the spacecraft IDs up with Horizons' own lookup (https://ssd.jpl.nasa.gov/api/horizons_lookup.api) instead of typing them from memory. Read the Horizons documentation for the available reference planes/frames and record the choice. Use one recent epoch (today's date, UTC). If Horizons does not list a spacecraft, mark it "status": "unknown" with its published orbit parameters (periapsis/apoapsis altitude, inclination, period) from the agency page, and set accuracy "approximate" with the missing angles omitted — those entries are skipped by the API until complete.

FILE FORMAT (data/processed/orbiters.json)
{ "frame": "<exact frame description>", "generated_utc": "...", "orbiters": [
  { "id": "mro", "name": "Mars Reconnaissance Orbiter", "agency": "NASA/JPL", "status": "active", "relay_capable": true,
    "accuracy": "approximate", "source": "<URL of the query>", "credit": "NASA/JPL-Caltech",
    "elements": { "a_m": ..., "e": ..., "i_deg": ..., "raan_deg": ..., "argp_deg": ..., "M0_deg": ..., "epoch_utc": "2026-11-14T00:00:00Z" } } ] }
Units: metres, degrees, UTC. a_m is the semi-major axis from the Mars centre (not an altitude).

DELIVERABLES (your folders only)
- data/pipeline/fetch_orbiters.py — queries the source, writes data/processed/orbiters.json, adds a manifest entry per source (id "orbiters.elements", license/credit lines as the source states them).
- data/pipeline/tests/test_orbiters.py — validates the produced file: required fields, 0 ≤ e < 1, a_m between 3.5e6 and 5e7 m, angles in range, epoch parses, ids unique.
- Report: for every spacecraft the source URL, the frame, the epoch, and the sanity values (periapsis/apoapsis altitude, period in hours computed from a_m with GM = 4.2828e13 m^3/s^2) next to the published values from the agency page.

ACCEPTANCE (paste real output)
1. ".venv\Scripts\python.exe" "data/pipeline/fetch_orbiters.py"   → lists each spacecraft with a, e, i and period
2. ".venv\Scripts\python.exe" -m pytest "data/pipeline/tests/test_orbiters.py" -q   → passed
3. With the API running (the CEO keeps it on http://127.0.0.1:8000): curl "http://127.0.0.1:8000/api/v1/orbiters/states?utc=2026-11-14T12:00:00Z" → one state per spacecraft with plausible altitude (a few hundred km for the low orbiters; Mars Express and TGO values should match their published orbits)

CONSTRAINTS: your folders only; no package installs; no API keys needed (Horizons is keyless) — never put a key in a file; polite request rate; do not invent elements.
OUT OF SCOPE: precise SPICE kernels (P2), the Mars globe texture (separate ticket).
